## 為什麼做這張

- **收掉最後一個已知的幸福差**：D027–D030 的實跑守衛都有一份 `KNOWN` 名單，其中 `seed516` 寫的是「T133 城市等級（微光之巔 +.02）」——實驗線讀進來就在 Lv.26 的城，住宅幸福多一項 `微光之巔`（`rankIdx >= 25 ? .02 : 0`，55217），本線 `day.ts` 給這一項的 `rankIdx` 一律是 0（`happy.ts` 的接口早就在）。搬完這一張，`seed516` 就該從名單上消失（守衛有「這一次沒有差了」的檢查，會逼著把它拿掉）。
- **它是玩家看得見的進度**：實驗線的「城市等級」是一條 26 級的長線階梯（拓荒營地 → 微光之巔），累積「城市點數」（人口＋幸福＋服務覆蓋）晉升，只升不降；晉升跳提示、有面板（等級名稱、進度條、下一級門檻）。本線的建造玩法目前沒有任何「城長大了」的回饋（只有人口里程碑與星等的獎金）。
- **只有一個模擬上的讀取者**（全檔 grep 過了）：住宅幸福的 `微光之巔` 項。其餘讀 `rankIdx` 的地方都不在本線的模擬裡：建築工具的解鎖門檻（`toolUnlocked458`：研究院 Lv.12、太空研究中心 Lv.22……本線的工具列沒有這些建築）、委託與合約（T385、T386，本線沒有）、AI 市長的建議（本線沒有）、成就（本線沒有）、企業層科技園的 `market`（39545：回退設定下企業層關，本線 D028 的科技園產值用「企業利用率 109＝1」）。所以這張的模擬半邊很小，重點在**每天的點數與晉升要跟實驗線逐位相等**。
- **對整城的影響**：起步城 8 種子 × 120 天的城市點數約 500–700（Lv.5–6），沒有任何讀取者，軌跡不變（預期 `d010-3d`、`d011-3d`、`d012-lab` 等黃金樣本 0 處不同）；只有讀進來就在 Lv.26 的老城（seed516）多 +.02。

## 施工前查到的事（只讀）

- **等級表**（38476–38503）：`RANKS` 26 條 `{name, threshold, unlock?}`，門檻 0、30、80、160、280、450、680、980、1360、1830、2400、3080、3880、4810、5880、7100、8480、10030、11760、13680、15800、18130、20680、23460、26480、29750；5 條有 `unlock` 文案（Lv.6、8、12、17、22 的「解鎖：…」與 Lv.26 的「城市巔峰榮耀：全城住宅幸福 +2%（永久）」）。
- **城市點數**（`computeCityPoints`，53633–53655）：純唯讀掃描，沒有亂數。掃全圖 `N×N` 格：`zone === 1`（住宅區）的格子數 `zoned`，每格的服務覆蓋計數 `c/5`（警察局或派出所、消防局或二號消防站或消防總部、學校、醫院或診所、公園，各算 1）加總 `covSum`；有建築（非 ref 格）且種類 ∈ {1、127、33、105}（住宅、社宅、住宅摩天樓）的，人口 `residentPopulation488` 加進 `popN`。`svcCov = zoned ? covSum/zoned : 0`；點數 `＝ max(0, round((popN + (cityHappy − .6)×400 + svcCov×800) × tq('D1', 1.05, 1) × tq('D4b', 1.10, 1)))`（`tq` 是科技樹的三元 helper，38549：科技做完才乘）。**幸福項用「相對 .6 的差」**，零人口新城恆為 0。

- **讀取者的時間**：住宅幸福項（55217）在 `tick()` 中段讀 `rankIdx`，晉升在 56133——**今天的幸福讀的是昨天的等級**（今天升級了，加成明天才有）。
- **存檔與讀檔**：寫 `rk: rankIdx`（66762，實驗線每次都寫）；讀（66967–66971）：`cityPoints = computeCityPoints()`（讀檔當下：表格與覆蓋此刻都重建完了，`cityHappy` 是新世界的預設 .6，所以幸福項是 0）；**有 `rk` 就原樣還原**（`clamp(d.rk|0, 0, 25)`，保留只升不降的歷史，即使現在點數暫時低於門檻），**沒有 `rk`（舊檔）就從點數往上爬**（`rankIdx = 0; while (…) rankIdx++`）。新圖歸零（51128）：`rankIdx = 0; cityPoints = 0`。
- **本線現有的接口**：`happy.ts` 的 `rankIdx`（`day.ts` 現在給 0）、`fields.ts` 的覆蓋場、`jobs.ts` 的 `residentPopulation488`（D024，`day.ts` 算人口時已經在用）、`Sim.edu.tech`（科技清單）。城市點數要的東西本線都有，不用新輸入。
- **時間**：這一張在 `stepDay` 多一趟整圖掃描（`N×N`，跟實驗線一樣）。D029、D030 都記著「推進一天餘裕只有 10–17%」；掃描要盡量折進既有的迴圈（`tickBld`、人口那一趟、`tickZone`），做完量測，餘裕縮小就要先折進去，不准放著。
