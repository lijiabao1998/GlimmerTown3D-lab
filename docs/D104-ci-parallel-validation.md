## 驗收與邊界（施工前）

1. 把可獨立執行的歷史與瀏覽器檢查拆成固定、完整的分片；先證明每個原始檢查都有且只有一個負責分片。共用前置與不適合拆開的順序情境可保留，不拆遊戲交易中途。
2. 保留原檢查內容、突變、圖像與效能門檻，不將未跑、失敗、逾時或缺證據改稱成功。原預設完整命令仍可運行。
3. 同一 CI runner 的計時守衛依序執行；並行只跨獨立 runner，避免互搶 CPU 造成假紅。美術與效能判斷仍依實際結果。
4. 任一必要分片缺失、重複、失敗、取消或沒有原始證據，都使聚合失敗。產物綁定同一來源／build／run，不混用其他提交的綠燈。
5. 本機先驗修正、分片完整性與失敗傳遞，完整矩陣以最終提交的 Actions 為準；已跑本機結果與未跑項目照實分列，不再先後重跑完全相同的本機及雲端全套作為推送前條件。
6. 以新的完整 CI 實際耗時對照基準，分開記排隊與執行。未完成前不宣稱加速倍率。
7. 不改工作流的 main 觸發、公開部署流程、遊戲來源 lease、兩條 2D 線、其他 PR 或舊分支。
