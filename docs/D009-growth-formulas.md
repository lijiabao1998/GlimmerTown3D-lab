## 為什麼做這張、為什麼拆

D000 的下一個里程碑是「D009 規則（取自實驗線）→ D010 建造 MVP」。讀完實驗線的每日 `tick()`（54945 起）之後，規則這一段的實情是這樣：

- **住商工的生長只有幾十行**（55577–55651）：
  - 需求三條；
  - 分區上找候選格，洗牌後每天最多長 3 棟；
  - 升級的閘門與機率。
- **但它讀的輸入由幾十個系統算出來**：
  - 幸福有 50 多項；
  - 地價；
  - 供電（配電路網＋T471 調度）；
  - 從第二天起，經濟閉環（T481／T482 商品、T485 物流）接手商工需求；
  - 住房市場（T488）接手住宅需求；
  - 企業（T489）把名目職位換成有效職位。
- 實驗線有 376 個開關（`window.__no*`／`__legacy*`），但**經濟閉環沒有開關**，每天收尾都會重建（56030）。
- 天氣、火災、災害都在生長之前消耗同一條亂數流 `R()`。

一張卡搬不完，所以拆成三張：

1. **D009（這張）生長核心公式**：生長這一層用到的公式，逐條從實驗線原始碼搬、逐項對拍。沒有畫面變化。
2. **D010 起步城逐日模擬**：把這些公式接成每日推進。上層系統先接實驗線自己的「還沒就緒」回退值。畫面上看得到城市自己長起來；跟實驗線做多種子統計對照，量出差距。
3. **D011 建造 MVP**：玩家自己蓋路、劃區、放電廠。

經濟、住房、企業這些上層，之後逐層加上，每層各自對拍。

## 做什麼

### 對拍的方法

`tools/lab-extract.mjs --part=d009`：
- 從實驗線 `index.html` 摘出每條公式的**原始碼文字**：函式照名字摘，`tick()` 裡的行內算式照錨點文字摘。
- 在 Node 的 `vm` 裡包成函式，外部依賴（`COV`、`LAND`、`R()`……）換成樁，餵同一批隨機輸入，存成黃金樣本 `src/content/samples/d009-formulas.json`。樣本裡記下實驗線 commit、每段的錨點與原始碼文字雜湊。
- 本線在 `src/sim/rules/` 寫純函式，單元守衛逐項比。
- 跑的是實驗線那一版的原始碼文字本身，所以只要本線寫錯一個係數或一個比較符號，就會對不上。

## 驗收（動手前寫）

1. **公式對拍**：F1–F10 每條 ≥2,000 組隨機輸入；格子類（F5 候選、F9、F11）≥200 張隨機小圖。本線的結果跟實驗線原始碼求值的結果逐項相等（`Object.is`，浮點也要一模一樣）。
2. **亂數順序**：F5、F6、F10 記錄每一次 `R()`／`ri(n)` 呼叫（含 n），序列逐項相等。
3. **供電實跑**：在實驗線頁面上，用 `GV.place` 蓋 ≥20 張隨機的道路＋電廠佈局，讀每一格的帶電狀態；本線 F11 算出的逐格相等。
4. **亂數產生器**：本線 `mulberry32` 跟實驗線那一行，同種子前 10,000 個值相等。
5. **注入要紅**：每條公式至少一種單點突變，對應守衛要變紅。例如：
   - 生長基準 0.10 改 0.11；
   - 每天上限 3 改 4；
   - 升級屋齡門檻 14 改 13；
   - 幸福基礎 0.62 改 0.63；
   - 帶電距離 90 改 89。
6. **出處**：黃金樣本記下實驗線 commit、每段的錨點與原始碼文字雜湊；抽取時錨點找不到或不唯一就停下來報錯，不猜。
7. **純度**：`src/sim/rules/` 不 import three、不碰 DOM、不用 `Math.random`、不讀現實時間。
8. **上線**：Node 守衛、煙霧、Actions、Pages 綠。
