# D034 摩天樓與巨廈合併（I）：2×2 塔、3×3 巨廈——城市長高的最後一步

## 為什麼做這張

- **玩家現在碰到的天花板**：本線的建築最高就是三級（lv3）住宅、商業；實驗線在城市夠快樂（幸福 > .55）時，會把**四棟相鄰、同類、二級以上、有電有水有污水接管**的住宅或商業合併成一座 2×2 **摩天樓**（k33 住宅塔、k34 商業塔），更快樂（> .6）時還有 3×3 **巨廈**（k105 住宅巨廈、k106 商業綜合體，人口與就業是九棟 lv3 的 1.35 倍）。D033 解掉三級的牆之後，這是下一道「城市會長高」的關卡。
- **這些種類本線早就認得、數得到，只是沒有東西會生出它們**：計數（`count.ts` 的 k33／34／105／106、塔與巨廈的人口與就業）、造型（`kindShapes.ts` 的 `tower`）、稅（`money.ts`）、`pickV406`、污水接管（D033）都有；缺的是合併本身。讀進來的實驗線存檔裡已經有塔與巨廈的（`ai120` 等），它們照規則算、只是不會再長出新的。
- **亂數流的最後一個缺口**：合併段在生長與財富之後、火災之前（55688），符合條件的簇每天抽亂數；本線沒搬，所以**任何有候選簇的城，亂數流從合併那天起兩邊錯位**。D033 之前沒有污水，候選簇根本湊不出來，所以一直看不到；現在玩家能蓋出來了，必須搬。

## 施工前查到的事（只讀）

1. **位置與閘門**（55676–55756）：在 30 天一次的財富移級（55676–55686）之後、火災（55757）之前。外層 `if(cityHappy>.55)`——**不快樂的城整段不跑、`R()` 零消耗**。`devSkylineBypass516B`（開發用繞過）在 `d23c18d` 沒有定義，`typeof … === 'function'` 恆假，不搬。`cityHappy` 是這一天走到這裡的值（糧食加減、污水廠減壓之後，D022、D033）；`dem` 是這一天的需求（`dem[1]` 住宅、`dem[2]` 商業，55586）。`sewNeed442`／`SEW_OK442` 是 D033 的。
2. **巨廈 3×3（k105 住宅、k106 商業）**，內層 `if(cityHappy>.6)`，**先於塔掃描**（街心大簇優先長大，塔撿剩下的）：
   - 掃描順序 `y` 0..N−3、`x` 0..N−3（列優先）；左上角 `mgDone` 就略過。
   - **定類**：窗內（`dy` 外圈、`dx` 內圈）**第一個**非 ref、`k` 是 1 或 2、`lv ≥ 2` 的建築的 `k` 當 `kk`（55702；T342e 把原本「左上角必為 Lv2+」放寬了）；找不到、或 `dem[kk] ≤ .25` 就略過。
   - **九格逐格判**（`dy`、`dx` 順序，先失敗先停）：`mgDone` → 失敗；同類、`lv ≥ 2`、通電、有水、（`sewNeed442` 時要接管）、沒起火 → 算一棟「實質」`subst++`；同類 `lv === 1`、沒起火 → 可以吸收（都更）；`k === 4`（公園）→ 記下、可以吸收；**沒有建築**、不是路、不是焦土、而且（分區＝`kk`，或沒分區的草地 `t === 2`）→ 可以；其餘一律失敗。`subst < 5` 也失敗。
   - **合格就先把九格標 `mgDone`**（擲骰失敗也標，所以同一簇不會被後面的塔掃描吃碎），再 `R() < .04`（每個合格簇每天一次）。成功：被吸收的公園成對撤掉覆蓋印（`stampCov('park', x, y, COVR.park, -1)`）；九格 `zone = 0`；根格 `{k:105|106, lv:1, v:0, age:0, pw:true, wa:true, h:1, sz:3}`、其餘八格 `{k, ref:[x,y]}`；`markLandDirty(x+1, y+1, 8)`；金色提示（住宅「🌆 住宅巨廈拔地而起！（居民 N 人）」、商業「🌆 商業綜合體開幕！（就業 N）」）。**被吸收的 lv1／lv2+ 建築沒有任何清理或補償**（格子上的 `bld` 直接被蓋掉）。
3. **塔 2×2（k33 住宅、k34 商業）**：掃描 `y` 0..N−2、`x` 0..N−2；根是非 ref、`k` 1 或 2、`lv ≥ 2`；`dem[kk] ≤ .3` 略過；**四格都要**：沒被 `mgDone`、非 ref、同類、`lv ≥ 2`、通電、有水、（`sewNeed442` 時接管）、沒起火。合格就 `R() < .02`（每個合格簇每天一次）；成功：四格標 `mgDone`，根格 `{k:33|34, lv:1, v:pickV406(tk,1,x,y,ri(4)), age:0, pw:true, wa:true, h:1, sz:2}`、其餘三格 `{k, ref:[x,y]}`，**分區不清**（跟巨廈不同）；金色提示（「🏙️ 住宅摩天樓落成！」「🏙️ 商業摩天樓落成！」）。`pickV406` 對 33／34 沒有排名表時回傳 `fallback`，所以 `v` 就是那次 `ri(4)`；JavaScript 由左到右求值，**每座成功的塔抽一次 `ri(4)`**。
4. **亂數的數量**：幸福 ≤ .55 → 0 次；每個合格的 3×3 簇每天 1 次 `R()`（幸福 > .6）；每個合格的 2×2 簇每天 1 次 `R()`，成功再 1 次 `ri(4)`。**同一天合併了，後面的火災、犯罪、疾病的抽籤位置全部不同**（實驗線同樣）。
5. **`tickBld` 是一天開頭建好的清單，合併不更新它**：後面的火災、犯罪、疾病迴圈（55757 起）讀 `tiles[i].bld`，被吸收的格子現在是塔或 ref 格（`k > 3` 或 `ref`），會被 `b.k<=3` 擋掉；本線 `hazard.ts` 用的是同一份 `tickBld`，要核對它對 ref 與 k > 3 的處理跟實驗線一樣。
6. **本線已經有的**：`count.ts` 的塔與巨廈計數、`towerPop488`／`megaPop488`（人口，D024）、`money.ts` 的塔與巨廈稅、`kindShapes.ts` 的 `tower`（k33 等的造型）、`pickV406`（D014，`land.ts`）、`SEW_OK`（D033）、`mgDone` 沒有。**缺**：合併迴圈、`merge` 事件（歷史格式 +1）、重播、城市模型同步、介面提示。`day.ts` 在 55691 已經留了註解位置（「摩天樓合併：起步城用不到」）。
7. **現有所有守衛的城都沒有候選簇**：`ai120` 第 1 天幸福 .676（> .55）但 `quads` 是 0（房子零散、多是 lv1）；Q 系列幸福 .55–.56、住宅隔著路排成兩排、沒有 2×2 實質簇；D022–D025 的 120 座城、起步城都一樣。所以**現有實跑守衛逐位不變**（要自造有候選簇的城才對得到這一段，見驗收 3）。
