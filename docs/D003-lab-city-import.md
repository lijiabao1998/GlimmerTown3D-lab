## 高度換算的理由

實驗線的投影是 `P(u,v,h)=[AX+(u−v)·32, TOPY+(u+v)·16−h]`（實驗線 `index.html:50238`），屬於 2:1 斜俯視，等於正交鏡頭方位 45°、仰角 30°。本線的鏡頭（`src/main.ts`）也是這個角度。

- 地面一格的邊長投影成 (32, 16) 像素，所以一個世界單位等於 32 ÷ cos 45° ≈ 45.25 px。
- 垂直方向要再乘 cos 30°，所以一格高 ≈ 39.2 px。
- 因此精靈圖的像素高度除以 39.2，就是 3D 的格數。

座標對應：實驗線的格子 (x, y) 對到本線的 (x, z)。兩邊的預設視角一致：+x 往右下、+z 往左下，光從左邊來。

**施工中自己抓到、照實記下的七件事**

1. **實驗線開機要 358 秒。** 骨架強制走 SwiftShader（WebGL 軟體渲染），實驗線卻全是 2D canvas、大量用 `getImageData`。改成用 CPU 畫 2D（`--disable-gpu`，`cdp.mjs` 加 `gl:false`）之後，開機 16.7 秒。
2. **精靈圖量到 0 張。** `SPR.bld` 的值是 `{img,night,ax,ay,w,h,sc}` 物件，不是畫布。
3. **實驗線拒絕匯入瘦身後的碼。** 它的 `load()` 無防護地讀 `rd`、`tre`、`zn`、`cam`，刪多了就讀不回來。改成只刪帶卡號的模組狀態和兩份日誌。
4. **縮在地塊中央的建築量得太矮。** 原本只比佔地菱形的後尖角，會被圍欄、鋪面先碰到，例如高鐵站只量到 0.28 格。改成逐欄比菱形上緣、取最大值：高鐵站變 0.88、文化藝術中心從 0.08 變 0.79。對縮在中央的建築，這個值仍是下界。
5. **住商工量錯了圖。** 第一版量的是 `SPR.bld` 舊圖集，住宅 3 級中位數 6.7 格，3D 市中心變成一片高塔林。跟 2D 並排才發現，實驗線從 T547 起畫住商工用的是街區精靈（`getBlockSprite547`），只有 1.84 格。改量單格街區精靈；1×1、2×2、3×3 街區的中位數相近，所以單格有代表性。
6. **2D 對照樣張第一版拍的是「匯入後」的城。** 電力狀態沒進瘦身碼，畫面滿地都是沒電的閃電圖示。改成在匯出前拍。
7. **兩處顏色跟實驗線不一致。** 橋面原本是木色，分區底色太重。對照實驗線，改成灰色柏油、淡底色。

**守衛有效性**（注入錯誤後判紅，還原後綠）

- 住宅巨廈（k=105）佔地多算一格 → 逐棟對帳紅（第 373 筆佔地 16≠9），也抓到 6 格重疊。
- RLE 展開少一個字元 → 5 條守衛紅。
- 模擬層加一行 `Math.random` → 純度守衛紅，點名 `city.ts:108`。
- 渲染漏畫商業綜合體 → 「場景建築數＝城市建築數」紅（944／945）。

**沒做成**

1. **密度沒照實驗線。** 實驗線把相鄰同類的住商工併成超街區，一排樓加後院草坪，有些格子不畫；3D 目前每格一棟，市中心明顯比 2D 密。要不要照做屬於規則 1 的全局觀感，D004 做兩三檔對照圖給業主挑。
2. **建築只是量體。** 大型地標（高鐵站的玻璃穹頂、貨櫃碼頭的吊車、醫學中心……）都還是方盒，要等 D004 的逐種配方。
3. **7 種沒有精靈的建築**，高度是本線自訂的預設，不是實驗線的數字；縮在地塊中央的建築，量到的是下界。
4. **只讀進城市的樣子。** 電力、水、交通、人口、預算都沒讀，也還不能在 3D 裡蓋東西（留給 D005、D006）。
5. **貼上的城市不會記住**，重新整理要再貼。只接受實驗線的 v1 格式；超過 2,000,000 字元會拒絕（同實驗線）；216 以上的大地圖沒測過效能。
6. **沒上實機手機**量幀率和記憶體；規則 5 仍然沒有數字化的預算。
7. **幾種對照還沒做。** 實驗線遠景會把建築藏起來（省效能），3D 全部畫；夜景、季節、四向旋轉的對照都還沒做。
8. **資料是快照。** 樣本碼和內容表是實驗線 `d23c18d` 的快照；實驗線之後改了種類或佔地，要重跑 `npm run extract`。
