# D030 城市活動（T299）：每 37 天一場，加成幸福、食物與稅

**基線**：D029 收工（`2409991`，見 `LOG.md` r29）

**授權**：業主 2026-09-28「全部做完吧」，2026-09-29「全做完就行啦，然後繼續下一波」。這是 [backlog](city-systems-backlog.md) 的 D 張（城市活動 T299），也是 D029 收尾建議的下一張。

## 為什麼做這張

- **D029 收工時，起步城「玩家實際玩到的本線」跟實驗線剩下的全部差異來自它**（D029 卡「整城軌跡」有逐種子的證據）：實驗線每個種子都在第 36–114 天有 16 個「有城市活動」的日子（三場），8 個種子的第一個分歧日全是第 36 天＝第一場活動的第一天；6 個種子活動日以外 104 天每一欄逐位元全等、活動日只差幸福；另外 2 個種子被活動的食物與稅率加成推上不同的成長路徑（人口第 38、41 天起分歧）。**把活動的輸入代進去，起步城 8 種子 × 120 天 960 個城日全等**（D029 驗收 3）——所以這是最後一個來源。
- 三個消費者的接口早就在了（住宅幸福的「城市活動」項讀 `eventHappy`、食物點數讀 `eventFood`、收入的整筆倍率 `cityEventIncome`），只是生產路徑永遠是「沒有活動」，只有守衛注入（D027 起 `injectInputs`、D028 的 `class2`）。這一張把「活動本身」（狀態、觸發、倒數、存檔）搬進來。
- **樣本現況**（`d027-lab.json`、`d028-lab.json`，實驗線回退設定，沒有新跑）：每天一列已經有 `ev`（`i`、`left`、`happy`、`food`、`tax`）。有活動的列：起步城 8 種子 128 列、長出來的存檔 24 份 120 列（其中 8 份**讀進來那天就已經在活動中**，`cev` 要從存檔還原）、自造城 J1–J17 61 列、D022–D025 的 120 座城 15 列（5 座，兩批同）、自造城 K 7 列；出現過的事件只有 4 種（`i`＝13、18、37、51），61 種的表逐條由 vm 對拍。

- **觸發與倒數**（`tick()` 54953–54954，`day++`（54950）之後、天氣之前）：`if (cityEvent) { cityEvent.daysLeft--; if (cityEvent.daysLeft <= 0) { toast('🎏 活動結束：' + 名稱); cityEvent = null; } } else if (pop > 50 && day > 15 && day % 37 === 0) { ei = Math.floor(streetHash(day, 7, 888) * CITY_EVENTS.length) % CITY_EVENTS.length; cityEvent = { i: ei, daysLeft: CITY_EVENTS[ei].days }; toast('✨ ' + 名稱 + '！' + desc, 'gold'); sFanfare(); }`。
  - **沒有亂數**（`streetHash` 只看 `day`：同一天所有城觸發同一個事件）；**`pop` 是前一天的人口**（這時還沒重算）；**活動結束的那一天不會同時觸發新的**（`else if`）；`days` 天的活動：觸發那天算第 1 天（倒數 `days`）、之後每天先減 1、減到 0 那天就沒有加成——實際有加成的日子＝`days` 天（樣本 `left`＝3、2、1 就是這樣）。
- **三個消費者**（都是「今天」的，因為事件步驟在當天的一開頭）：住宅幸福項「城市活動」（55179）＝`cityEvent ? happy : 0`；食物點數（55293）× `cityEvent ? food : 1`；當天收入（56028，所有收入項加總之後）`Math.round(income × tax)`——**`tax` 恰好是 1（例如 T299 原版的「豐收節」）也照樣取整**。本線 `cityEventIncome(income, eventTax)` 的行為已經一樣（D011）。
- **狀態與存檔**：`cityEvent`（`{i, daysLeft}` 或 `null`）**入存檔**，欄位是實驗線**既有**的可選欄位 `cev`（寫 66764：`cev: cityEvent ? { i, d: daysLeft } : 0`；讀 66963：`d.cev && typeof d.cev.i === 'number' && 0 ≤ d.cev.i < 61 ? { i, daysLeft: (+d.cev.d) || 1 } : null`，舊檔缺＝無）；新圖 `cityEvent = null`（51111）。所以**不是新號、不需要業主定格式**（規則 9：存檔用實驗線的格式）。
- **其他讀 `cityEvent` 的地方，全檔 grep 過了**：收割視覺聯動（61567：豐收節與秋收慶典期間全圖強制收割態，畫面）、公民代理的「社交需求」+.15（63269、66369，不在 `tick()` 裡）、三個面板（65687、66285、66427）、`GV` 鉤子（68900–68901）。**模擬讀它的只有上面三個消費者。**
- **本線現有的接口**：`happy.ts` 的 `eventHappy`、`food.ts` 的 `eventFood`、`day.ts` 的 `Class2In.eventTax`、`money.ts` 的 `cityEventIncome`；`lab.ts` 有 `streetHash`（57805，D026 起）；`save.ts` 的存檔欄位寫法有 D025（`sup`、`gds`）與 D026（旗標層）的先例（「範本有這欄、或現在有東西才寫」）。
- **時間**：事件步驟在 `s.day++` 之後、天氣之前；不動亂數流（本線 D010 起 `weatherStep` 是唯一在生長前抽亂數的一步）。

## 做什麼

1. **`src/sim/rules/events.ts`**（新）：`CITY_EVENTS`（61 條，照抄）、`eventStep(cur, day, pop)`（純函式：倒數、結束、觸發，回傳新狀態與這一天「開始／結束」哪一條）、`eventOfSave(cev)`（讀檔驗證）。不碰 three、DOM、`Math.random`、現實時間；沒有亂數。
2. **`src/sim/day.ts`**：`Sim.cityEvent`（存檔欄位 `cev`）；`stepDay` 在 `s.day++` 之後接 `eventStep`；三個消費者由當天的事件補進（守衛注入的 `hazard.eventHappy`、`class2.economy.eventFood`、`class2.eventTax` 蓋過去）；`DayReport.cityEvent`（當天的事件與有沒有剛開始／剛結束）；`simHash` 在有活動時多吃 `i` 與剩餘天數；`simFromSave` 還原 `cev`。
3. **`src/io/save.ts`**：`saveCode` 寫 `cev`（有活動才寫、範本有這欄就寫成 0；都沒有就不加欄位，存檔位元組不變）。
4. **介面**：活動開始與結束跳提示（照實驗線的字：`✨ 名稱！說明`、`🎏 活動結束：名稱`）；☰「收支明細」在有活動時多一列「✨ 活動加成 稅 ×N（名稱，剩 D 天）」；☰「幸福構成」本來就有「城市活動」一項（現在生產路徑有值了）。**世界歷史不記活動**（不加事件種類、城市格式不動，見「要業主定的事」）。
