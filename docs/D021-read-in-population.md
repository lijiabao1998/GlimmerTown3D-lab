- **住宅塔、巨廈的居民沒算進人口**（D020 卡「沒做成的事」1）：實驗線 `pop＝popN＋towerPop488＋megaPop488`（55246），塔（k33）與巨廈（k105）的居民不看有沒有電；本線 D010 起 `pop＝popN`。
  - 讀進來的種子城：實驗線推進一天後 1,400 人（全部來自塔與巨廈），正式清運；本線 0 人，走小城那一支。垃圾量（人口×.05）與 500 人門檻都差。
  - D009、D010 卡都沒寫這一項，D020 才第一次講明。
- **讀檔之後、第一天之前，本線的 `pop` 是 0**：實驗線讀檔之後 `pop` 已經是住宅人口總和（T510 把 `load()` 包了一層，見下）。
  - 這是 D020 的另一份平行施工（備份在工作階段分支 `1938332`，不進 `main`）跟實驗線頁面對拍時抓到的；`main` 上的 D020 只在建築卡的註解提到「`simFromSave` 人口 0」，沒有處理。
  - 人口 ≥ 500 的城讀進來，第一天的 `sewNeed442`（55011：昨天的 `pop` ≥ 500）實驗線是 true、本線是 false；「高密度污水」（Lv3 以上、沒接污水管，−.04，55229）本線少扣。
- 兩件都只在**讀進來、已經有樓的城**出現：起步城、新城沒有樓，預建城不到 500 人。本線的介面目前讀進來的城只能看，所以這張補的是模擬本身的口徑（Node 守衛、之後能玩讀進來的城時才碰得到）。

## 做什麼

1. **每天**（`src/sim/day.ts`）：主計數迴圈數塔與巨廈的居民（`residentPopulation488`，55108、55110），`pop＝popN＋towerPop＋megaPop`（55246）。
2. **讀檔**（`simFromSave`）：`pop` 起頭改成讀檔之後的住宅人口總和（`loadPop488`：k1、k127、k33、k105 各自 `residentPopulation488` 加總取整）。
3. **守衛**：新樣本 `src/content/samples/d021-lab.json`（`tools/d021-lab.mjs` 在實驗線頁面錄：每座城讀檔後的 `pop`、推進一天後的 `pop`），`tools/unit-d021.mjs` 逐座比；D020 守衛裡種子城「本線自己推進一天」原本只量不判，改成判。

## 不做什麼

- 主計數迴圈其餘的固定就業（焚化廠 k62 +12、回收中心 k29 +4、商業塔 k34、商業綜合體 k106，55246 尾端與 55050–55119 一帶）不做：另開一張卡，不影響人口與垃圾量。
- 讀檔之後、第一天之前的 `jobs`（68455–68457）不做：本線第一天才算，狀態列的就業在第一天之前還是 0。
- 存檔裡的 `sk`／`dt`（生病、死亡）本線讀檔不還原，實驗線讀檔的人口排除這些人：沒搬（疾病、死亡是第 2 類系統）。
