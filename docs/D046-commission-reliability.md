2. 鋼材小數累計在本線舊檔讀入、儲存、重讀、分享碼來回皆不消失。`cms385` 仍是舊 2D 讀器可接受的整數格式，本線精度放有版本與狀態配對驗證的附加欄位；2D 忽略附加欄位時保留委託與整數進度。不得宣稱未修改的舊 2D 能保留小數，也不得暗中改 2D。
3. 委託的進行中進度常駐且可打開詳情；顯示與結算同源，完成、放棄、過期、重新整理會更新。加入真正透過逐日糧食出口完成委託的驗收，不直接塞達標進度冒充。
4. 太空研究中心 Lv.22 建造鎖不變；從正常城市點數結算自然升級的測試，並確認解鎖提示。不得用測試直接提升 rank 假裝自然解鎖。

## 相容性方案

- 新發單政策：`3d-capabilities-v1`。原始 `cmsHash` 浮點乘法及 11 個委託 id 不動；先保留 D045 三選一裡可行的順序，再從相同雜湊序列補可行候選，不足三條就顯示實際數量。它只影響未接受的新選項，已接受的 id、開始日、完成與期限不變。D045 的原文對拍繼續測原始抽選，D046 另測本線能力篩選，不能再宣稱新選單與 2D 每張相同。
- `cms385` 的六欄不改，`acc` 向下取整供舊 2D 接受；`cms3d: {v:1, base, acc, done?}` 保存精確小數與重接時的原完成清單，`base` 完整配對 act/st/acc/hold/n/done。2D 改過任何一欄但留下舊 extension 時，不補回過期小數。畸形 extension 只丟精度，不丟有效主委託。D045 已保存的小數 cms385 直接救回。
- 本線存讀／分享碼保留小數與重接項目的先前完成紀錄。經未修改的舊 2D 重匯出保留進行中委託、整數進度及其他完成紀錄，但丟失小數（小於 1 單位）與該進行中重接項目的先前完成標記；再次完成後仍會重新記入。兩條 2D 倉庫沒有修改。
- `src/sim/eventRegistry.ts` 集中登記所有現存 0–24 碼；18 policy、19 budget、20 research、21 spec、22 techdone 屬格式 8，23 depleted 屬格式 9，24 cms 屬格式 10。CITY_FORMAT 仍是 10，歷史 hv2/3 不變。偽稱舊版本卻帶新事件時放棄不可信歷史、保留城市快照，不能錯解碼。
