# D039 玩家決策進世界歷史：政策、預算、研究、選方向、科技完成（城市格式 8）

**基線**：D038 收工（見 `LOG.md` r38）
**授權**：業主 2026-10-05「全部做完吧」，回應 D038 匯報的建議「先決定第 1 項（玩家決策進世界歷史）」。這是 [D032 卡](D032-policies.md)「要業主定的事 1」、[D038 卡](D038-tech.md)「要業主定的事 1」的答案：**記**。
**依據**：CLAUDE.md 規則 4「世界歷史只增不改。蓋、拆、改建、入住、遷出都記成事件；三種玩法都從同一份歷史讀。歷史格式一改，存檔就要加版本號、舊檔要能讀」。

## 為什麼做這張

- 建造玩家的決策現在只有「蓋、拆、放、復原」進歷史（D011）、「處置」進歷史（D026）。**稅率調了、法規開了、服務預算動了、研究開始了、城市方向選了**都只存在存檔的 `pol`／`sb`／`tech343`／`spec386` **當下的值**——歷史讀不到「哪一天做了什麼決定」。
- 考古玩法要讀「這座城的歷史」：一座城為什麼在某一年人口掉頭（宵禁？工業稅調到 2.0？），要從決策讀得出來；一生玩法的城市也一樣。三種玩法共用同一份歷史，這是地基。
- 科技完成是模擬每天自己發生的事（不是玩家按的）；跟「開始研究」成對，才讀得出「哪一年學會了什麼」。

## 做什麼

## 不做什麼

- **不用歷史重建模擬**：模擬的狀態仍然從存檔欄位讀（`pol`／`sb`／`tech343`／`spec386`），歷史是紀錄、不是第二個真相來源；`decisionsOf` 只給守衛核對與面板顯示。
- **不回頭補舊城的決策**：2D 存檔讀進來時已有的政策、完成的科技**沒有**事件（匯入事件是起點；`decisionsOf` 的「起點」參數就是匯入那一刻的狀態）。
- 其他每天自己發生的事（升等、里程碑、星等、城市活動）**不在這張**：它們是模擬的結果、不是決策，要不要記是另一個決定（見卡末）。
- 不加時間軸視圖（300 年示範的時間軸是 D002 的生成歷史，不是這份）。

## 施工中查到的事

1. **`from` 撞名**：`unpackHistory` 的取欄位函式把名叫 `from` 的欄位一律當成 D034 合併的「被吸收建築編號」尾巴；政策與預算事件的 `from`（改之前的值）被讀成一個陣列，第一個壞資料守衛就紅。改成只有 `merge` 才走那一支。
2. **事件要帶「改之前的值」**：第一版 `policy` 只存新值（`[18, dDay, 碼, 值]`）。但讀檔重播不知道起點（存檔裡只有現在的 `pol`，2D 存檔讀進來時的政策沒有事件），歷史讀不出「稅率從多少調到多少」。改成 `[18, dDay, 碼, 改之前, 改之後]`，歷史自己讀得出差；起點只有守衛核對重播時才需要（它知道自己的起點）。
3. **讀檔會多幾筆 `restyle`**（D012 起的既有行為）：所以「存→讀→再存」比的是決策事件與不含 `restyle` 的歷史，不是整份逐位元組。
4. **六個舊守衛寫死了「格式 7」**：D010（`CITY_FORMAT === 7`）、D011 的「比這一版新」案例（`f: 8`）、D019（`CITY_FORMAT === 7`）、D026（`d3.f = 8` 要被擋）；全部改成 8／9。**D032 的一個守衛斷言「政策與預算不該寫世界歷史」——這張卡正是要改它**，改成斷言「真的改了才記、各一筆」。
5. **兩份實驗線樣本的碼雜湊變了**：D032、D038 的 rt 樣本是「本線存的碼給實驗線讀」，本線存的碼現在帶格式 8 與決策事件，雜湊對不上（守衛抓到）。各只重錄 rt 部分（`d032-lab.mjs --part=rt` 4 筆、`d038-lab.mjs --part=rt` 6 筆）；**實驗線讀回來的列兩份都逐位元不變**——格式 8 的存檔實驗線照樣讀得到（規則 9）。
6. **CSS 又漏了一組規則**：`#ch` 照著 `#tc` 的作法借共用的面板樣式，這次用正則分段改選擇器列，但 `index.html` 有一行裡寫了兩組規則（`… { margin-top } #hs .row button, … { min-height: 44px }`），只改了第一組，關閉鈕只有 34px 高——手機煙霧的「按鈕 ≥ 44×44」抓到。改成逐組解析、並且 `#ch` 的每一組都核過。
7. **`techdone` 記的日子**：研究在 `stepDay` 裡推進時 `s.day` 還是前一天的編號（後面才 `s.day++`），生長、災禍事件記的都是「正在結算的這一天」，所以 `techdone` 記 `s.day + 1`；玩家的決策在結算之前，記 `s.day`。歷史的日子因此永遠不往回走（守衛核）。

## 沒做成的事（照實講）

1. **模擬自己發生的大事沒記**：升等、里程碑獎金、星等、紓困、城市活動（61 種）、災害保險理賠——它們是模擬的結果、不是決策；大事記只列玩家的決定與科技完成。要不要一併記是另一個決定（見下）。
2. **2D 存檔讀進來時已有的政策、預算、完成的科技沒有事件**：匯入事件是起點，大事記從匯入之後才有；讀進一座已經有 20 個科技的城，大事記是空的（面板的標題不會講「這座城其實已經研究過很多」）。
3. **歷史不驅動模擬**：模擬的狀態仍從存檔欄位讀；歷史是紀錄。`decisionsOf` 只給守衛核對與面板。如果哪天想改成「事件溯源」（從歷史重算現在），是另一個大決定。
4. **大事記只讀、不能篩選、不能點進去**，最多列最近 300 筆；沒有時間軸圖。
5. **沒有上實機。**

## 要業主定的事

1. **要不要把模擬自己的大事也記進歷史**（升等、里程碑、星等、城市活動、紓困）：記的話大事記就成了「這座城的編年史」，考古與一生玩法讀得到每一次轉折；成本是歷史多幾種事件（格式 9、舊檔照讀）、存檔略長。我的建議：**記升等與里程碑**（量少、意義大），城市活動先不記（61 種、每 37 天一場，量多）。
2. **三種玩法怎麼讀這份決策歷史**：建造玩法現在有大事記面板；一生（陪一個市民活一輩子）與考古（廢墟裡讀歷史）要怎麼用「第 N 天宵禁開了」「第 M 天選了工業港城」，是玩法設計，不是搬運。
