## 為什麼做這張

- D016 的對照圖看得出來：3D 的公園只有沙地十字路加三棵樹，實驗線的公園有噴水池、長椅、遊具、涼亭、球場。
- 公園（k4）是最便宜、最常蓋的設施，實驗線放下去會抽一次 `ri(9)` 決定變體（51667），九種長得都不一樣；本線的畫法不看變體，九種都一樣。
- D007 的造型表在公園那一行寫「實驗線沒有精靈」，是錯的：實驗線有 `SPR.park`，九種。

## 做什麼

1. **造型**（`src/content/kindShapes.ts`、`src/render/kindArt.ts`）
   - 公園（k4）改成照變體畫：九種各照上表的設計擺 3D 小件（石徑、長椅、花、池塘、噴泉、綠籬、滑梯、鞦韆、涼亭、球場、野餐桌），顏色取實驗線原文的色碼。
   - 畫法需要知道變體：`KindCtx` 多一個 `v`（只有公園讀）。件的快取鍵本來就有變體（D015 `civicKey`），不用改。
   - 造型表公園那一行的註解改正。
2. **只動公園**：動手之前先把全部非住商工種類（樣張城每一棟、各變體）的幾何雜湊錄成一份表；改完之後，公園以外的每一種都要跟表逐位相同。
3. **D015 的首次建黃金樣本重錄**：有公園的情境，公園那幾棟的幾何變了。重錄之後，其餘主人（街區、其他建築）照上一條驗。

## 不改什麼

### 施工中遇到、照實記下

1. **動手前的表證實了問題**：公園九個變體的幾何雜湊九個一樣（變體不進畫法）。
2. **玫瑰園第一版 204 個三角形**，超過卡上的 200：玫瑰、花從小方塊改成貼地的小片（2 個三角形），降到 76。
3. **收尾推上去 CI 紅燈**（`c10bf56`，[run 36447461509](https://github.com/lijiabao1998/GlimmerTown3D-lab/actions/runs/36447461509)）：Node 守衛「只動了公園」說公園以外 150 多種都變了。
   - 原因不在畫法：CI 用 Node 24、本機 Node 22，兩版的 `Math.pow` 最後一位不一樣（取樣 19,999 個值有 1,958 個不同；sin、cos、exp、log、hypot 等都一樣）。three 的 `Color` 把 sRGB 轉線性色用 `Math.pow`，動手前那張表又是逐位元雜湊，所以只在錄表的那一版 Node 上對得上。
   - 修法：雜湊之前每個值先取到 1e-6（`tools/d018-kinds.mjs`）；表從動手前的原始碼（`7d21ff4`，另開工作樹）重錄，Node 22 與 24 錄出來逐字相同；現在的程式在兩版 Node 上公園以外都＝表。Node 24 另跑全套 Node 守衛 211 項 0 NG。
   - 模擬沒有這個問題：`src/sim`、`src/io` 只用 2 的整數次方（精確值）。
