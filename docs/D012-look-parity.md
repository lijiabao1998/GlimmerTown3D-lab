## 為什麼做這張

1. **外觀跟實驗線對不上。**
   - 實驗線每次讀檔，都依當下的街區密度與地價重挑住商工的外觀變體 `v`（T531）。本線讀檔保留存檔裡的 `v`。

   - 本線預設 B 檔照實驗線切分：沒被街區認領的格（D0）、被吸收的 1×1（T555），都畫成草坪。
   - 種子城 924 格有 380 格沒畫（41%）。建造時更明顯：D011 劇本城第 121 天 256 棟有 182 棟沒畫（71%）；D011 對照那一跑（種子 5162026）第 121 天 105 棟有 65 棟沒畫。

## 施工前查到的事（只讀，四路並行研究）

### 實驗線的 T531

- **什麼時候跑**：`load()` 最後一步 `ensureVariety531(true)`（67035 → 66848–66862）。匯入分享碼（`importShareCode` 64902 → `load()` 64916）、繼續遊戲、存檔槽、`GV.load` 都走這一條。
  - 每日 `tick()` 開頭也叫一次 `ensureVariety531(false)`（54946），但同一個世界只跑一次；讀檔之後那一次什麼都不做。新世界第一天會跑，那時通常還沒有住商工。
- **怎麼挑**：依格索引順序走過每一棟住商工根格（k＝1／2／3，跳過 ref），`v ← pickV406(k, lv||1, x, y, v)`（53185）。
  - `pickV406` 看 7×7 都市密度（`urbanDens406` 53175）、該格地價 `LAND`、兩個固定雜湊（`streetHash`、8×8 街廓的 `hashLocal479`）。
  - 不抽亂數，也不看鄰居的 `v`，所以走的順序不影響結果；世界沒變就重複執行恆等。
  - 本線 D009 已經搬了 `pickV406`、`urbanDens406`（`src/sim/rules/land.ts`、`grid.ts`），200 張圖逐格對拍過。
- **讀檔時的地價**：`LAND` 不在存檔裡，讀檔時重算，重挑用的是最後一次 `rebuildCov`（66965）的結果。
  - 輸入：存檔的服務預算 `sb`（66964）、存檔的犯罪旗標 `cm`（66916）、建築與樹算出的污染；交通、捷運加成在讀檔時都是 0。
  - **實驗線的怪處**：噪音場 `NOISE` 讀檔時不重算，用的是這一頁上一個世界留下的（只有每日 tick 才重建，54949、54997）。所以同一頁先玩過別的城再讀檔，重挑結果可能不同。開新頁讀檔時 `NOISE`＝0。
- **`v` 只影響畫面**：模擬裡讀 `v` 的地方都是寫（新建 55622、升級 55649、摩天樓 55751、讀檔重挑）；人口、工作、稅、污染、地價、幸福都不看 `v`。
- **切分會跟著 `v` 變**：1 級住宅的 `v` 是 0／5／10 時是別墅（`arNameVilla600` 70747），別墅自成 1×1、不跟鄰居併（`rciMergeable547` 70454、`rciBlockOrigin547` 70461）。重挑 `v` 會改變哪些格是 D0、哪些被吸收。
  - 實測（本線同一套切分）：種子城重挑前 D0 370、被吸收 10 → 重挑後 360、7；AI 城 97、2 → 93、5。

### 本線現況

- **`v` 存在兩個地方**：模擬與存檔讀 `sim.w.tiles[i].bld.v`；畫面讀 `city.buildings` 的 `v`（`sim.root` 把兩邊連起來，每天由格子同步到城市）。重挑要兩邊一起改：只改城市，隔天被格子蓋回去；只改格子，下次讀檔的重播跟存檔對不上。
- **讀檔路徑**：開頁、換城、貼分享碼、測試出口都走 `cityView.ts` 的 `load()`。有模擬的城走 `loadCode`（重播歷史、跟存檔對帳）；唯讀的樣本城（種子城、AI 城、全種類、沒有 `d3` 的分享碼）只建城市模型，**沒有地價**，現在沒辦法重挑。
- **讀檔時的地價**：本線 `simFromSave` 用預設服務預算、沒有犯罪旗標、沒有噪音。實測把 AI 城的 `sb` 與 2 格犯罪、種子城自己的 5 個噪音源加進去，地價會變 135／396 格，但重挑結果 0 棟不同。現有樣本兩邊一致；任意分享碼不保證。
- **歷史**：`CITY_FORMAT` 目前 3，但讀檔從來沒有檢查它；緊湊列 `T_CODE` 0–7；`packHistory` 沒有 default，沒寫到的種類存檔時會悄悄消失。
- **D011 對拍工具的墊片**：`tools/d011-parity-lib.mjs` 的 `variety531` 在預建城那段先照實驗線重挑一次再比（8 個種子都是 11 棟、跟實驗線相同）。本線讀檔自己會重挑之後，墊片就是多餘的，錨點要重錄。

### C 檔

- D004 定義：「先照實驗線切。還沒被認領的格子（D0）當成新起點，依掃描序用同一套長法補切；被吸收的 1×1 照畫」。C 是本線自己的補法，實驗線沒有對應。
- D005 當時選 B 的理由：「C 把 D0 全補成建築，工業區從 2D 的十幾棟變成六十棟，比實驗線擠很多」。業主這次定了「該畫的還是要畫」。
- 美術：C 走同一條配方、點綴、窗、立面、飾條的路；非住商工的造型不分檔。沒有任何卡記過 C 專屬的畫面問題。
- 成本：切分本身很便宜（Node 暖機後每次 0.3–0.6 ms，C 比 B 多約 0.3 ms），多的是幾何。樣本城量過：種子城三角形 69,598 → 93,610、AI 城 67,396 → 74,566，draw call 都是 15。**建造中的城在 C 檔從沒量過**，B 檔沒畫的比例又更高（53–71%），要重量。
- 穩定：C 不會「閃」（沒有格子變回草坪），但街區重切比 B 多一點（每天延續下來的格有 3.0% 換街區，B 是 2.0%）。

## 做什麼

### 1. 讀檔照實驗線重挑外觀（T531）

- 新函式放在 `src/sim`（不 import 渲染）：照 `ensureVariety531` 走過住商工根格、呼叫本線的 `pickV406`，有換的同時寫進格子與城市兩邊，回傳換了哪些。
- 有模擬的城：放在 `loadCode` 的對帳之後；退回「只用存檔」的每一條路也照樣重挑（實驗線每次讀檔都挑）。
- 唯讀的樣本城：讀檔時替它算一次地價（同 `simFromSave`，不重播、不保留模擬），重挑之後拿城市去畫。
- 之後每天推進不再重挑（實驗線讀檔之後 tick 那一次是空的）。
- 讀檔時的地價照本線現況（預設預算、沒有犯罪旗標、沒有噪音），不在本卡補；差異寫進「沒做成的事」。

### 2. 重挑記進世界歷史（規則 4：只增不改）

- 新事件 `restyle`：`{day, t:'restyle', x, z, v}`，一棟一筆，只記換了的，日子＝讀檔那一天。不能復原（不是施工）。
- 格式：`CITY_FORMAT` 3 → 4；緊湊列種類碼往後加 8（`[8, dDay, x, z, v]`），既有的 0–7 不動；`hv` 仍是 2（列的編法沒變）。
- 讀檔：格式 3 的舊檔照讀，讀進來照樣重挑、記事件。比這一版新的格式（`d3.f` > 4）不猜，退回只用存檔並講明。
- 重播：`restyle` 把那一格住商工根建築的 `v` 設成事件的值，不動屋齡；那一格不是住商工根格＝重播失敗，講出第幾筆。
- 驗型別：座標 0..n−1、`v` 0..9999（同 grow）、列不能比種類長。
- 建築卡不列 `restyle`：那是讀檔時的視覺遷移，不是城裡發生的事；歷史照記。
- 唯讀樣本城的事件只在記憶體（它們本來就不存）。

### 3. 看不見的建築畫出來：預設改 C

- 預設 B → C。B 在 ☰ 選單與 `?blocks=b` 照樣切得到；A、`?blocks=off` 不變。
- 網址參數只認 a／b／c／off（研究發現 `?blocks=constructor`、`__proto__` 會通過 `in` 檢查，畫成 C 卻沒有選單項目，卡片寫「CONSTRUCTOR 檔」），順手修成 `Object.hasOwn`。
- 串台提醒：這是本線自己的畫法。實驗線 D0 仍畫草坪（T633 §1 還沒挑檔），實驗線不跟著改。本線的碼拿到實驗線，外觀照實驗線自己的畫法。

### 4. 對照圖（規則 1）
