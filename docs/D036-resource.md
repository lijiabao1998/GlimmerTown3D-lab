# D036 資源開採（M）：油井、礦場每天抽油抽礦，耗損跟著存檔走

**基線**：D035 收工（見 `LOG.md` r35）
**參考**：2D 實驗線 `lijiabao1998/GlimmerTown-lab` @ `d23c18d`（v13.43），只讀。行號都指 `index.html` @ `d23c18d`。
**授權**：業主 2026-10-04「全部做完，做完之後匯報」。這是 [backlog](city-systems-backlog.md) 的 M（D024 起每一張都寫著「`suppliesGain`／`oilGain`／`oreGain` 一律 0」）。

## 為什麼做這張

- **實驗線每天在主計數迴圈裡抽油、抽礦**（55131–55146）：油井 k49 站在油田格（`RESOURCE===1`）上，每天抽 `min(3, 240 − RDEP)`；礦場 k50 站在礦藏格（`RESOURCE===2`）上，每天抽 `min(2, 240 − RDEP)`。抽出來的量累計進該格的耗損 `RDEP`，同時加進當天的 `suppliesGain`、`oilGain`／`oreGain`；`RDEP` 到 240 這格就停產。
- **這三個量進經濟**（55300–55308）：`fuelMade`（煉油廠把當天的油煉成燃料，吃 `oilGain`）、`steelMade`（鋼鐵廠吃 `oreGain`）、`supplies += suppliesGain − fuelMade − steelMade`；再進一般工業的供應品需求（56044）、經濟報表的 `raw`（56152）。本線的 `economy.ts` **早就搬了這幾行，只是 `count.ts` 裡這三個量一律 0**。所以有油井、礦場的城：供應品庫存永遠不增加、煉油廠與鋼鐵廠永遠沒原料、燃料與鋼材不產——跟實驗線差一大截。
- **資源圖不入存檔**（53219–53223）：`RESOURCE` 由種子決定（兩張獨立的低頻值噪聲、門檻 .74、只鋪在陸地），讀檔時 `genResource(seed)` 重建（66895）。
- **耗損 `RDEP` 要入存檔**：開採歷史無法從種子重建，所以存檔有稀疏可選欄位 `rdep`＝`[[格索引, 已開採量], …]`（66730、66765；讀檔 66946–66951，舊檔缺欄位＝全數未耗損，量夾在 240 以內）。本線讀檔現在丟掉這個欄位——有挖過的存檔讀進來，每一格都從滿的開始。

## 施工前查到的事（只讀）

1. **要搬的函式**：`genResource(sd)`（53225–53237）、`makeNoise(rand, G)`（37227–37238，值噪聲：`Float32Array` 存格點、平滑插值、三層疊加 .6／.3／.1）、常數 `RESOURCE_STOCK=240`、`OIL_RATE=3`、`ORE_RATE=2`（39447–39448）。**`makeNoise` 的格點存成 `Float32Array`（單精度）**——照抄，不能用普通陣列，否則門檻邊上的格子會判得不一樣。
2. **種子**：`genResource(seed)` 用的是存檔的種子（66895），本線 `save.seed`；`mulberry32(sd ^ 0x7c2f19)`、`mulberry32(sd ^ 0x1a4d63)`，兩個噪聲場各 64×64，**不碰全域亂數**（本線同樣不能動 `s.rng`）。
3. **抽取的位置**：在 `tick()` 主計數迴圈裡、逐棟、讀的是「這一格」的 `RESOURCE`／`RDEP`（`b.k===49` 用 `idx(x,y)`，油井是 1×1）。建築 `pw` 不看——**沒電的油井照樣抽**（55131 沒讀 `b.pw`）。所以抽取順序不影響結果（每格只被自己的井動），可以放進本線 `count.ts` 現有的迴圈。
4. **本線已經在的**：`count.ts` 137–138 行 `owN++`／`mnN++`，`economy.ts` 171–176、362–371 讀 `suppliesGain`／`oilGain`／`oreGain`。這張只補「抽取」與「`RDEP` 的狀態與存檔」。
5. **存檔寫回**：`rdep` 要寫回（本線的模擬會改它）。稀疏：只存非零格、按格索引升序（`save()` 66730 的 for 迴圈順序）；全空就不寫（`null`，66765）。讀進來的 `rdep` 裡不是配對、長度不夠、索引出界、量 ≤ 0 的項目照實驗線略過（66947–66950）。
6. **沒有搬的**：油井、礦場的**蓋法**——實驗線 `canPlace('oilwell')` 檢查油田格（51430）、`canPlace('mine')` 檢查礦藏格（51431）；本線目前沒有這兩個工具（`build.ts` 的工具清單沒有 `oilwell`／`mine`），**所以玩家蓋不出新井，只有讀進來的城有井**。要不要加工具（還有資源圖的小地圖視圖、`drawResourceHints459` 的游標提示、市長 AI 的找井址 54809–54810、54881–54882）是另一張卡；這一張把「有井的城每天抽、耗損存得住」做對。
7. **氣井 k117**（`gaswell`）：實驗線也要油田格（51430 `oilwell||gaswell`？見下），但它的產出走 `gasDep485`（T485 物流），不是 `RDEP`。**這張不碰氣井**（`count.ts` 沒有 117 的抽取；實驗線也沒有）。

## 施工中查到的事

1. **只能看的大圖要略過資源圖**：D012 的 1000×1000 空圖 `viewCode`（只讀、重挑外觀）加了 `genResource`（兩張 64×64 噪聲、逐格插值一百萬格）之後，整輪 Node 守衛裡這一項紅了（門檻 < 1,500 ms）；那個模擬永遠不推進（`forRestyle`），所以資源圖給全 0（`new Uint8Array(nn)`）。改完 D012 守衛量到 819 ms。
2. **三張舊守衛的接線錨點跟著動**：D024（`tallyBuildings(w, tickBld, fert)` 多了 `s.res`）、D028（`countMore(mc, w, i, b, fb)` 多了 `res`）、D036 自己的 live 守衛（`genResource(save.seed, w)` 多了 `forRestyle ?`）。三處都是「錨點要剛好一處」的機制抓到的，不是行為差異。
3. **實驗線 `makeNoise` 的格點是 `Float32Array`**：照抄；用普通陣列，門檻邊上的格子會判不一樣（突變抓得到）。
4. **vm 突變守衛的等價突變要剔除**：型別陣列越界寫入（被默默丟掉）、`amt>=0`（量是 ≥ 0 的）、浮點對 `|0` ——這些改了原碼也不改結果，不能算「抓到」，已換成不等價的版本。
5. **`unit-d036-live` 的相對效能守衛**：絕對值（≤ 5 ms）在機器忙時誤紅，沿用 D035 的做法——跟資源圖清空的同一座城交錯量、判比值。

## 沒做成的事（照實講）

1. **玩家蓋不出新的油井、礦場**：`build.ts` 的工具清單沒有 `oilwell`／`mine`，也沒有 `canPlace` 的油田／礦藏檢查（實驗線 51430／51431）。**只有讀進來的 2D 存檔裡本來就有井的城，井才會抽。** 資源圖的視圖（小地圖上標油田礦藏）、游標提示（`drawResourceHints459`）、市長 AI 找井址（54809、54881）也沒搬。
2. **看不到資源圖**：油田與礦藏在 3D 畫面上沒有任何標示；只有點井的卡片講得出「站在油田上／礦藏上／沒有資源」。
3. **氣井 k117 沒碰**（走 `gasDep485` 物流，不是 `RDEP`；實驗線的 `RDEP` 也不管它）。
4. **開採不進世界歷史**：抽取是每天的狀態變化、不是玩家行為，跟糧食、供電一樣不記事件；「井枯竭」也沒記成事件。考古玩法若想讀到「這座城的油田什麼時候挖完」，要另外決定（見「要業主定的事」2）。
5. **資源圖只對 72 與 108 兩種邊長（vm）、72（頁面）驗過**：本線目前的地圖邊長範圍內，種子與地形是隨機的，但邊長不是；1000×1000 的只能看的城故意不算資源圖（見「施工中查到的事」1）。
6. **沒有上實機**：手機效能只有無頭 Chrome 的 draw call 與 Node 的毫秒數。

## 要業主定的事

1. **要不要讓玩家蓋油井、礦場**（連同資源圖的視圖、游標提示）：現在有井的城只能靠讀進 2D 存檔。這是一張新卡（工具、`canPlace` 規則、小地圖視圖），也牽涉到介面要放在哪一排工具。
2. **井枯竭要不要記成世界歷史事件**：記的話，考古玩法讀得到「這座城的資源什麼時候用完」；不記，耗損只存在存檔的 `rdep` 欄位。歷史格式要多一種事件（規則 4：版本號、舊檔照讀）。
